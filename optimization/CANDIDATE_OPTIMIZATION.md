# 候補CSVからの転位最適化

プロジェクトのルートから実行します。

```powershell
python optimization/optimize_candidates.py
# 先頭3候補だけで動作確認
python optimization/optimize_candidates.py --limit 3
# 入出力を指定
python optimization/optimize_candidates.py --input tooth_search/candidates.csv --output optimization/output_custom
# 4候補を並列実行
python optimization/optimize_candidates.py --workers 4
# 初期値4点で一次探索（上位候補や未収束候補は後で初期値を増やす）
python optimization/optimize_candidates.py --workers 4 --starts 4 --output optimization/output_screening
# 検証
python -m unittest discover -s tests/automated
```

依存ライブラリはルートの `requirements.txt` に記載しています。最適化にはNumPy・SciPyを使用します。

## 入力と設定

`optimization_config.json` で入力CSVと出力先、摩擦係数、圧力角、遊星数、転位範囲、かみあい率、必要すきま、トリミングON/OFF、初期値数などを設定します。設定内のパスはこのJSONの場所を基準にします。コマンドラインのパスは実行ディレクトリ基準です。

CSVの必須列は `ma, mc, zs, zp1, zr1, zp2, zr2`。列順は自由、UTF-8のBOMにも対応します。CSVには圧力角・遊星数がないため、歯数探索時と同じ値を設定してください。`a_min/a_max`、`reduction`、`status` は元行として保存し、探索条件や成立保証としては使用しません。中心距離範囲と減速倍率は再計算します。転位範囲やトリミング設定を変えても、CSVで既に除外された候補が復活するわけではありません。必要なら歯数探索からやり直します。

## 計算と制約

各候補の歯数・モジュールを固定し、独立変数 `[xr1, xr2, 共通中心距離]` を0〜1に正規化してSLSQPで順効率を最大化します。中心距離の範囲は3かみあいの転位和/差から再計算します。

共通中心距離から `xs, xp1, xp2` を復元するため、共有P1の転位は一つです。P1の歯先半径も論文式(83)を一つだけ計算して両かみあいで使います。各区間に別々の転位が存在するだけでは採用しません。

全5歯車の転位上下限、歯先円と基礎円、近寄り・遠のきかみあい率の非負、全かみあい率上下限、基礎効率・全体効率の0〜1、両段の遊星間すきま、内歯P1–R1/P2–R2のインボリュート・トロコイド干渉、設定に応じたトリミングを同じ設計点で評価します。固定歯数の等配組付けも再確認します。S–P1のインボリュート干渉、外径、歯強度、切下げ、歯先厚さの条件は対象外です。

SLSQP実行前に、内歯の遠のきかみあい率の上限を保守的に評価します。中心距離下限とリング転位上限から遊星の歯先半径を大きめに見積もり、作動圧力角も最小値を使います。それでも上限が負で許容誤差を超える候補は、既存の遠のきかみあい率制約を満たせないため `geometry_rejected` として計算を省略します。合格は全条件の成立保証ではありません。CSVでは従来どおり「未収束」、実際の最適化試行数は0になります。

トロコイド・トリミング式は既存モデルに準拠し、式の定義域外は不合格にします。歯形全体の衝突検証とは異なります。

## 結果

- `results.csv`: 番号、最適化判定、5歯数、減速比、順効率（％）、逆効率（％）、3かみ合い率、5転位の順で全候補を1行ずつ保存します。
- `summary.json`: 実行設定、処理数、成立数、総収束数、最良候補。

最適化判定は、収束して全制約を満たした解があれば「収束」、それ以外は「未収束」です。減速比は入力速度/出力速度の絶対値（例えば96.24）です。歯数はzs、zp1、zr1、zp2、zr2、転位はxs、xp1、xr1、xp2、xr2の順です。不成立行の効率・転位・かみ合い率は空欄にします。入力のモジュールは候補CSVに残り、実行条件と最良候補の詳細はsummary.jsonに保存します。

採用にはソルバーの成功と、最終点の全制約余裕が `-feasibility_tolerance` 以上であることの両方を要求します。解なしは「実行した局所探索で収束した可行解が得られなかった」であり、解の不存在の証明ではありません。

候補別JSONと反復履歴の保存は行いません。完了した候補をCSVに逐次追記し、終了時に入力順で並べ直します。毎回すべての対象候補を最初から計算し、同じ出力先のCSVと集計を上書きします。以前の結果を残す場合は出力先を変更してください。

## 時間短縮

設定ファイルの `"workers": 4` が候補の並列数です。オプションなしの通常実行で4候補を同時に計算します。`--workers N` を指定した場合はその実行だけ設定を上書きします。初期値・制約・採用条件は変えません。CPUとメモリを使用するため、速度向上は環境に依存します。少数候補では起動コストで遅くなる場合があります。

`--starts N` は設定の初期値数を上書きします。回数を減らすと高速になりますが、良い解や可行解を取りこぼす可能性があります。一次探索を少ない初期値で行い、上位候補や未収束候補を別CSVに抜き出して12〜30点で再確認する方法があります。途中で成功した時点での打切りは実装していません。

計算内部では、直近の同一評価点を最大128点再利用して有限差分に伴う再計算を減らしています。最終解はキャッシュを消して制約を再評価します。
